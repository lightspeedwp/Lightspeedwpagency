# Authority and Proof Framework

## Proof categories to standardise

### Performance proof
- Core Web Vitals (with INP as a primary interactivity metric)
- TTFB and cache hit ratio (where measurable)
- Page weight and critical CSS footprint targets

### Publishing throughput proof
- Time-to-publish from brief to live
- Pattern reuse ratio (new pages assembled from existing patterns)
- Governance compliance (tokens usage, pattern locking adherence)

### Commercial proof
- Conversion rate shifts (baseline vs after)
- Revenue per visit, email capture rate, subscription conversion (where applicable)

### Reliability proof
- Incident frequency, rollback time, uptime data, patch cadence

## Placement strategy

### Homepage
One metric strip near the hero, not buried in the footer.

### Systems pages
Inline metric callouts tied to the system claim (e.g., "INP under 200 ms for key templates" aligned to CWV guidance ranges).

### Case studies
A consistent "obstacle -> system change -> measurable result" module.

## Micro-proof block patterns

### Proof chips
Single-line evidence: "Migrated X posts with zero downtime" + "See method" link to Systems page.

### Method cards
Short method statement + link to playbook.

### Authority quotes
Use the Automattic testimonial as a "platform credibility" block near the LSX Design system story, not only on generic pages.

## Case study structure template

### Context
Organisation type, constraints, baseline metrics.

### System diagnosis
What failed: content model, performance budget, editor safety, governance.

### System rebuild
Tokens, patterns, templates, workflow changes.

### Distribution outcomes
Search, AI feature inclusion changes (where measurable), structured data improvements.

### Commercial outcomes
Conversion, revenue, lead quality.

### Transfer
Documentation, governance model, training delivered.
