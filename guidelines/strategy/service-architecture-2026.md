# Service Architecture Reframing 2026

## Core problem with the current framing

Current "service lists" mirror how agencies sell labour (design, development, support, hosting), which makes LightSpeed comparable on surface area rather than outcomes.

The 2026-2027 opportunity is to sell systems: content supply chain, editorial governance, design token governance, block pattern libraries, and measurable distribution outcomes (search + AI search).

## Rename and rebundle into a three-tier model

### Foundation tier
**Offer name:** Publishing System Foundation
**Best for:** firms that need a defensible base (performance, governance, tokens, patterns) before growth activities.

**Deliverables:**
- System audit: IA, content model, template map, pattern map, analytics/measurement plan.
- Design token baseline: theme.json v3 token system aligned to design source of truth.
- Pattern governance baseline: pattern hierarchy, slot rules, locking policy, and editorial safety.
- Performance baseline: CWV targets, caching strategy, image pipeline, CSS budgets (INP-first).
- AI visibility baseline: crawlability checks, structured data baseline, definitional pages plan.

### Growth tier
**Offer name:** Conversion and Content Operating System
**Best for:** teams with regular publishing and measurable acquisition targets.

**Deliverables:**
- Topic cluster system + editorial governance; update cadence, workflows, and QA gates.
- AEO pattern library: FAQ patterns, comparison patterns, "definition blocks," citation-ready formatting.
- Experimentation and CRO: conversion instrumentation, landing page factory patterns, and an experiment backlog.

### Enterprise tier
**Offer name:** Publishing Platforms and Commerce Infrastructure
**Best for:** media, membership, high-volume commerce, or multi-brand groups.

**Deliverables:**
- Structured content architecture: entities, taxonomies, content types, relationship rules.
- Distribution resilience: paywall/subscription markup strategy where needed.
- Observability: performance monitoring, logging, release governance, incident playbooks.
- Editorial scale: permissioning, pattern locking, multi-brand variations.
